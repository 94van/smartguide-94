## 启动

需要 Node.js 22.13+、pnpm 11。首次安装：

```bash
pnpm install
pnpm dev
```

- 患者端：http://localhost:5173
- 管理后台：http://localhost:5173/admin
- 模拟接口：http://localhost:3000/api/health

患者端和后台统一使用 5173 端口。按 Ctrl+C 一起关闭网页和接口服务。

当前这台 Mac 也可双击 `start.command`（已安装依赖后），脚本会尝试使用 Codex 自带 Node。

如果终端提示找不到 Node，可先执行：

```bash
export PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH"
pnpm dev
```

手机演示：电脑与手机连接同一个 Wi-Fi，手机访问 `http://电脑局域网IP:5173`；同时放通本地防火墙的 5173 和 3000 端口。手机端会自动连接同一 IP 的 3000 接口。

## 3–5 分钟演示脚本

1. 同时打开患者端和管理后台。初始患者为万穗，A023，心血管内科 218 诊室。
2. 在患者端点击「去这里 · 开始导航」，地图显示门诊楼 1F 到服务台路线；点击「模拟到达」后完成签到。
3. 下一项为 218 诊室。开始导航，分别点击路线中的 1F、2F 标签查看分层路线，模拟到达并进入候诊。
4. 在后台或患者端连续模拟 5 次叫号，直到 A023，点击接诊并开检查。
5. 模拟缴费 ¥280，导航到医技楼 CT 室。路线显示下楼、电梯和院区步道。模拟到达并完成检查。
6. 生成模拟报告，返回 218 诊室复诊；患者端可查看报告展示。
7. 模拟缴药费 ¥36，导航到西药房、模拟到达、确认取药。本次就诊完成。
8. 后台选择「普通门诊 → 取药」并重置，可演示跳过 CT 的另一条流程。

测试通行变化：定位到门诊楼 1F，目标选 218。后台暂停 A 区电梯后，路线改走楼梯；同时打开无障碍模式，显示不可通行提示。恢复电梯后重新出现可用路线。

## 已实现

- 蓝白患者界面、深色可缩放和拖动的 SVG 地图，响应式手机布局、关怀大字模式。
- 3 栋楼、5 张楼层图、30 个科室与设施。院区建筑示意可点击进入楼层。
- 搜索名称与别名（如取药、拍片、抽血），科室点选导航，分层展示、语音播报（依赖浏览器支持）。
- Dijkstra 路线计算，电梯/楼梯跨层连接、跨楼栋步道、无障碍模式、路段封闭绕行。
- 签到、候诊、叫号、模拟支付、检查、报告、复诊、取药，两套就诊流程。
- 后台更新科室名称和开放时间、封路、电梯停运、演示推进、重置和操作记录。
- REST API 统一状态，1.5 秒轮询联动，版本号冲突保护，数据保存到 `data/demo.json`，重启后保留。
- 定位二维码由服务器生成，内容为 `hospital-demo://location/<节点ID>`；小程序支持扫码，H5 提供模拟扫码链接和位置选择。

## 小程序

使用微信开发者工具导入 `miniapp/` 目录。已提供原生 WXML/WXSS/JS，无需另外编译或安装 npm 依赖。

- 默认 `touristappid` 用于本地开发导入；真机预览或发布需要配置你自己的 AppID。
- 开发工具中允许「不校验合法域名」，运行本地演示接口。
- 开发工具可用 `http://127.0.0.1:3000`；真机需在页面底部填写电脑局域网地址，例如 `http://192.168.1.8:3000`。
- 支持导诊流程、搜索、楼层 Canvas 地图、路线、模拟到达、模拟叫号、扫码和手选定位、关怀模式。
- 小程序与 Web 共用同一个 API 的地图、流程和状态。WebMCP 仅属于浏览器增强功能。
- 当前环境没有微信开发者工具及真实 AppID，源码已提供，尚未进行微信编译器及真机验收。

## 地图与科室替换

`shared/hospital.mjs` 中的 `specs` 定义建筑、楼层和科室，`nodes` 是通行点，`edges` 是无向通行边。地图组件和路线引擎读取同一坐标，距离单位是演示米数（坐标 × 0.22，楼层连接为等效通行距离）。

`components/hospital-map.tsx` 渲染楼层与院区底图。替换真实地图时，必须同时校准底图坐标、房间入口、节点与边；不能只更换图片而沿用虚构路网。后台目前可编辑名称/时间和通行状态，暂不提供拖拽绘制路网的编辑器。

## 接口

| 请求                                  | 用途                                                                           |
| ------------------------------------- | ------------------------------------------------------------------------------ |
| GET /api/health                       | 服务状态                                                                       |
| GET /api/state                        | 当前导诊与通行状态                                                             |
| GET /api/hospital                     | 地图、科室、楼层、流程定义                                                     |
| GET /api/route?from=service&to=cardio | 当前通行条件下的路线                                                           |
| GET /api/qr?id=cardio                 | 定位二维码 SVG                                                                 |
| POST /api/action                      | advance / call / locate / arrive / accessible / elevator / block / poi / reset |

所有写操作必须提交当前 `version`，过期版本返回 409；患者端自动读取新状态并提示重试。未到达任务地点、未叫到当前患者或无可通行路线时，后端拒绝违规推进。

## 当前边界

本项目是可信的本地模拟演示，不是生产医院系统。管理后台无登录，API 允许局域网跨域，适用于本机或可信演示网络，未部署公网。未接真实支付、真实诊断、蓝牙定位、HIS 或真实医疗报告。入口、室内与全程导航使用 Three.js，SVG 为兼容回退。建筑是虚构的空间示意，不是测绘或 BIM 模型。

## 三维空间入口

首页进入 Three.js 院区空间：拖动旋转、滚轮或双指缩放，点击建筑或底部建筑标签进行聚焦。右侧楼层按钮可展开门诊楼的 3 个楼层，恢复按钮回到院区全景。点击「进入院区」或建筑卡片，镜头推进至建筑入口后进入对应的 1F 导诊地图。患者端顶部「三维院区」可再次打开空间。

三维渲染使用独立动态加载模块 `lib/scene/campus.ts`，布局位于 `components/spatial-entry.tsx`。模型含玻璃幕墙、楼板、雨棚、树木、通行步道和微光效果，住院楼仅 1F 开放导诊。切出空间会释放 WebGL 资源；后台标签页暂停渲染，移动设备降低像素密度，尊重系统减少动态效果的偏好。WebGL 不支持或加载失败时，可直接打开二维导诊。

本次三维改动已通过 TypeScript、生产构建和页面 HTTP 检查，未进行浏览器画面及实际 GPU 渲染验收。

## 三维室内导航

进入院区后，主导航面板也使用 Three.js。每层以开放屋顶的立体空间呈现诊室、墙体、门洞、桌椅、电梯和楼梯。点选诊室或搜索目的地后，路线直接沿三维走廊显示。楼层选择和建筑选择继续使用统一地图数据。

点击「沿本层路线漫游」切换至近地步行视角，预览当前楼层的连续路线；该操作只移动镜头，不修改患者定位，也不会自动完成就诊。跨层路线通过楼层标签分段查看；到达仍需明确点击「模拟到达」。地图拖动会退出自动漫游，重置按钮回到鸟瞰视角。WebGL 不可用时才使用备用二维地图。

实现文件：`components/interior-map.tsx`、`lib/scene/interior.ts`。接口轮询相同版本数据时不再重复重建场景，从而保持相机操作连贯。

## 整栋选层与适老主题

患者端现在直接进入单屏建筑工作区。整栋建筑保持固定楼层高度，选中楼层实体高亮，其他楼层保留透明楼板和立面。切层不会重置已旋转的相机角度。导诊单、搜索、楼层选择和到达操作浮动显示，主页面不滚动；完整就诊步骤可在导诊单内展开。

左上角主题选择：

- 医院蓝绿（默认）：页面 #F3F6F4，按钮 #1B6B7A，文字 #1A2B24，说明 #4A5C55；导诊单独立采用 #FFFBF2 纸色和 #D4C08A 表格线。
- 高对比大字：白底、#111111 正文、#0B4F6C 按钮、更大的任务文字。
- 空间展示：保留深色展示风格。

主题偏好只保存在当前浏览器。成功消息使用叶绿，警告使用琥珀色，错误使用浅底、红字和红边框；主按钮不用红色。适老界面使用不透明面板和清晰边框，三维模型仍保留非选中楼层的透明效果。

## 全程导航与操作反馈（最新）

原来的贴地逐层漫游已替换为「全程导航 · 跨楼层 / 楼栋」。一次规划覆盖走廊、电梯/楼梯、院区步道和终点诊室，三栋楼与整条路线同时在三维空间显示。默认相机固定、位置标记平滑移动，避免转弯时转动镜头。允许手动旋转查看，但点击诊室不再自动推动镜头。

导航弹层支持暂停、0.5×/1×/2× 演示速度、从起点重看，页面隐藏时暂停计时。电梯和跨楼栋段显示明确提示；通行条件改变导致路线变化时，自动暂停并重算。没有可通行路线时不允许播放。演示结束必须点击「确认模拟到达」才能更新模拟位置，不自动完成就诊任务。

每个就诊步骤完成后，患者端显示大号确认卡，说明已完成任务与下一步；初次打开已完成的历史状态不会误触发庆祝。操作错误显示持续的红字红边警示，需要用户确认关闭。网络异常提示先核实最新状态，避免重复操作。最后取药完成进入结束状态时显示庆祝卡和彩带，无声音、无频闪，可关闭；减少动态效果设置下不播放彩带。

新增 `tests/journey.test.mjs` 检查跨楼栋/楼层连续性、段落边界、不可达路线和反向路线标识。当前仍是虚构地图与定位的演示，不等同于已接真实医院系统的生产部署。

## 路线防穿墙修正

科室导航点位于走廊侧门口。南侧房间之间和外侧的通行折点由路网定义，平层距离按折线长度计算；三维导航、备用平面地图和小程序读取同一折线。跨楼路线通过建筑入口门洞抵达院区步道。全程视图的科室使用带门洞的墙体，不再使用实心方块。标记按路线弧长平滑移动，避免在直角处斜切。`tests/geometry.test.mjs` 检查全部平层边的房间避让、门口点位、路径方向与转角采样。
